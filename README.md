# 圖面工坊

既有圖面（點陣掃描檔）的尺寸改圖工具。原圖不被改寫，圖形不隨尺寸變形——
以白底遮罩蓋住原尺寸文字，再依尺寸表疊上新的數值與公差，輸出標示「不依比例，尺寸以標註為準」的試作圖。

## 執行

```bash
python3 -m http.server 8000
# 瀏覽器開啟 http://localhost:8000
```

請用本機伺服器開啟，不要直接以 `file://` 點兩下開啟：瀏覽器會封鎖畫布讀取，導致
PNG 輸出、列印與框選自動辨識全部失效。

標註字體用 Google Fonts 的 IBM Plex Mono。若廠內無法連外，會退回系統等寬字體——
預覽與輸出用的是同一套字體，兩者仍然一致，只是字形與原圖略有差異。

## 圖上直接操作

| 操作 | 動作 |
|---|---|
| 點標註 | 選取該欄位（左側表格同步highlight） |
| 拖曳標註或錨點 | 移動文字位置 |
| 拖曳遮罩八個控制點 | 調整遮罩大小 |
| 拖曳藍色圓點 | 改字級 |
| 方向鍵 / Shift+方向鍵 | 微調文字 1px / 10px |
| 雙擊標註、或工具列「改值」 | 就地修改數值 |
| 拖曳空白處 | 平移畫面 |
| Ctrl/⌘ + 滾輪 | 以游標為中心縮放 |
| Esc | 取消框選／就地編輯／選取 |

選取後會在標註旁浮出工具列：字級增減、方向切換、公差位置、置中、改值、刪除。

框選新尺寸時只要框個大概，系統會自動貼齊墨跡邊界，並判斷文字方向、字級與公差位置
（藍框＝遮罩範圍，綠虛線＝判定為公差的部分）。**不辨識數字內容**，舊值仍須人工讀取填入。

## 目前內容

`assets/` 內為 5 張底圖（1414×2000 JPG），分兩個類型群組：

| 類型群組 | 圖面 | 可填尺寸 |
|---|---|---|
| 錐尖頂針 P | D4P001000001、B4P001000001、C4P001000002 | 各 13 個 |
| 球頂／異型 J | C4J002000001、D4J013000001 | 尚未設定，原圖可查看 |

三張錐尖頂針的欄位為：凸緣外徑、中段軸徑、導柱徑、中心孔徑、尖端內圓角、
段高 H1–H5、總長、頸縮徑、底徑。遮罩座標以原圖像素量測後校準。

## 放進自己的圖面

在畫面上按範本清單右上角的「**＋ 底圖**」即可，不需要改程式：

1. 選圖檔 → 填圖面名稱／圖號、類型群組、材質
2. 建立後自動切到「設定範本」
3. 「**框選圖框範圍**」框住原圖下方要被蓋掉的標題欄（綠色虛線就是目前範圍）
4. 「**框選新尺寸**」逐一建立可填欄位——框個大概，系統會自動貼齊墨跡並判斷格式

**支援 PNG／JPEG／WebP。瀏覽器無法直接讀 TIF**，圖庫是 TIF 的話要先批次轉檔
（IrfanView、XnConvert 之類的工具都可以整批轉，轉成 JPEG 品質 90 以上即可）。

上傳的圖檔存在瀏覽器的 IndexedDB，範本只記錄引用，所以草稿與快照不會重複複製圖檔。
**備份 JSON 不含圖檔**——換電腦時除了匯入備份，還要把上傳過的圖面重新上傳一次；
內建在 `assets/` 的圖不受影響。

也可以改用程式碼內建：把 JPG 放進 `assets/`，再編輯 `index.html` 最上方的 `SEED` 陣列。
座標一律以原圖像素為準，與畫面縮放無關。

## 資料層

| 層 | 內容 | 更新時機 |
|---|---|---|
| 範本主檔 templates | 底圖引用、欄位、遮罩、預設值、版本號 | 按「保存範本新版」 |
| 工作草稿 drafts | 自己持有的範本副本、實際尺寸、公差、圖面資訊 | 編輯後自動保存（去抖動 300ms） |
| 已存圖面 saved | 完整草稿快照 | 每按一次「另存圖面」新增一筆 |
| 畫面狀態 ui | 目前範本、模式、選取、分類、縮放 | 操作過程更新 |

快照內含範本副本，所以日後修改範本不會改寫舊圖面。

保存於瀏覽器 IndexedDB，依瀏覽器與網址來源隔離（不同瀏覽器、localhost 與 127.0.0.1、
不同連接埠都不共用）。清除網站資料會移除紀錄，沒有伺服器備份或多人同步。
換電腦請用「備份資料」匯出 JSON 並保留整個專案資料夾——備份不含底圖 JPG。

復原保留最多 60 個檢查點，重整頁面後消失，沒有重做。

## 字形比對辨識（實驗過，未採用）

試過用字形比對自動讀出框選處的舊尺寸值。`tools/glyph-eval.py` 是當時的字模建立
與評估程式，三張已校準圖面做留一驗證的結果：

| 指標 | 數值 |
|---|---|
| 字元正確率 | 93.4% |
| 整串正確率 | 52.9% |
| in-sample 整串正確率 | 70.6% |
| 格式檢查＋信心門檻 0.50 | 覆蓋 54.9%、精確率 89.3% |

**判定為不可上線**：精確率 89% 等於每 9 筆自動填入就有 1 筆錯，使用者仍得逐筆核對，
省不了時間又增加誤簽風險。

瓶頸有兩個，且互相獨立：

1. **切字**——遮罩含公差堆疊的欄位會被切碎（`Ø9.73` 切出 16 個字），`R1` 則黏成一個。
   in-sample 測試證明即使比對完美，整串上限也只有約 76%。這是有界的工程問題。
2. **字模樣本太少**——`9`、`R`、`+` 各只有 1 個樣本。就算切字修好，
   單字 93.4% 套到 6 位數字串是 0.934⁶ ≈ 66%，仍達不到 90%。這不是調參能解決的。

要繼續走這條路，合理的做法是讓工具在日常使用中自己累積樣本：每次有人框選建立欄位
並輸入舊值，就同時得到「字形影像＋正確標籤」。累積到每個字元有 20 個以上樣本後再重測，
精確率達 98% 才開啟自動填入。

## 尚未實作

自動 OCR、任意圖片上傳、幾何變形、尺寸公式與跨欄位連動、工程合理性檢查、
圖號配發、BOM／ERP 串接、權限、正式審核與變更紀錄、多人共用與版本歷史。

必填檢查只確認欄位非空白，不代表設計檢核通過。系統不驗證數值是否合理、
公差上下限是否顛倒、孔徑是否小於外徑。
